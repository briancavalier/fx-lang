# Phase 3.1 JavaScript effects runtime protocol

Date: 2026-06-10

## Purpose

This note defines the small JavaScript runtime protocol used by Phase 3.1 to
make ordinary Phase 3 effect programs executable through
`fx compile --target js`.

The protocol is intentionally narrow. It supports operation requests, handler
dispatch, ordinary handler returns, and explicit `resume` for the examples in
`examples/phase-3/`. It does not settle the full semantic law model for
multi-shot resumptions, scoped effects, coeffects, masking, or resource
cleanup.

## Representation

Effectful generated code runs as computations. A computation is represented by
a runtime object with a `run(handler, continuation)` method.

```js
__fx.effect((handler, continuation) => {
  // either call continuation(value) for an ordinary result,
  // or dispatch an operation request to handler.
})
```

Pure values are lifted into computations with `__fx.pure(value)`. This lets the
emitter compile only effectful regions to the protocol while keeping ordinary
pure declarations on the existing direct JavaScript path whenever possible.

## Operation requests

An operation request carries:

- a stable operation key, using the resolved module-qualified operation name;
- an ordered payload array;
- a continuation supplied by the runtime dispatch path.

The request shape is internal to the runtime helper:

```js
{
  operation: "module.operation",
  payload: [/* values */],
  resume(value) { /* continue from the operation call */ }
}
```

Generated operation calls use `__fx.perform(operation, payload)`.

## Handlers

A handler is a table of operation clauses plus a `return` clause:

```js
__fx.handle(actionComputation, {
  operations: {
    "module.raise": (message, resume) => defaultValue,
    "module.choose": (left, right, resume) => resume(left),
  },
  return(value) {
    return value;
  },
})
```

When an operation is requested, the nearest handler whose `operations` table
contains the request key receives the payload values plus an explicit `resume`
function. Ordinary action completion goes through the handler's `return`
function.

If no handler matches an operation, the request escapes to the next outer
handler. If no outer handler exists, the runtime throws `Unhandled fx operation
<operation>`.

## Resumption

`resume(value)` re-enters the suspended continuation at the operation call site
under the same handler boundary. This is enough for the Phase 3.1 `Choose`
example:

```fx
choose(left, _right, resume) ->
  resume(left)
```

Phase 3.1 does not define static laws for storing, duplicating, or repeatedly
calling a resumption. The runtime should support the behavior needed by the
compiled examples and should document any practical one-shot or multi-shot
constraint if one is introduced.

## Unsupported subset

Checked Phase 3 constructs outside the implemented protocol should fail during
`fx compile --target js` with an `unsupported-effect-runtime` compiler
diagnostic. They should not become parser or checker diagnostics.

Unsupported diagnostics should point at the source construct that prevents
emission.
